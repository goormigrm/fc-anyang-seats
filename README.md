# FC안양 예매현황

FC안양 홈 경기(안양종합운동장)의 티켓링크 구역별 잔여석을 받아 경기장 배치도 위에 예매, 매진 현황을 그리고 PNG로 저장하는 웹 페이지입니다.
서버 없이 `index.html` 한 장으로 동작합니다.

- 주소: https://goormigrm.github.io/fc-anyang-seats/ (GitHub Pages, `main` 브랜치 루트. 푸시하면 바로 반영)
- 검색엔진 노출은 막아 두었습니다 (`noindex`).

## 파일

| 파일 | 내용 |
|------|------|
| `index.html` | 화면, 그리기, 입력, 스크린샷 인식 전부 |
| `emblem.js` | 경기장 가운데와 스토리 이미지에 넣는 앰블럼 (PNG를 base64로 담은 상수 `EMBLEM`) |
| `.gitignore` | `좌석스크린샷/`, `예시/` (개인 캡처, 예시 이미지는 올리지 않음) |

외부 라이브러리는 글자 인식용 `tesseract.js@5.1.1`(jsdelivr CDN) 하나입니다. 인터넷이 안 되면 스크린샷 인식만 안 되고 나머지는 그대로 씁니다.

## 쓰는 순서

1. 경기 정보: 상대팀(2026 K리그1 11팀), 경기 날짜, 시각(10:00~22:00, 30분 단위)을 고릅니다. 스크린샷을 넣으면 화면 위쪽에서 읽어 자동으로 채웁니다.
2. 잔여석 입력 (셋 중 편한 방법)
   - 스크린샷 인식: 티켓링크 앱 '등급/좌석 선택' 화면을 등급마다 눌러 구역 목록이 보이게 캡처하고, 여러 장을 한 번에 Ctrl+V 하거나 파일로 고릅니다. 인식된 구역은 표에서 노랗게 표시되니 숫자를 확인합니다.
   - 표에 직접 입력: 구역별 '잔여' 칸에 숫자를 넣습니다. 비우면 '정보 없음', 0이면 매진입니다.
   - 매진 버튼: 매진된 구역은 '매진' 버튼만 누르면 잔여가 0으로 들어갑니다.
3. 집계 시각 '지금'을 누릅니다.
4. '현황판 저장'(1280x1040, 2배 해상도) 또는 '스토리 이미지 저장'(1080x1920)을 누릅니다. 휴대폰에서는 '스토리로 공유' 버튼으로 공유 창에 바로 보낼 수 있습니다.

다음 집계 때는 숫자를 바꾸기 전에 '지금 숫자를 기준으로'를 누르면, 그 사이 예매된 좌석이 구역마다 +N 으로, 카드에 합계로 나옵니다.
새 경기를 시작할 때는 '새 경기: 잔여 모두 지우기'를 누릅니다 (최대 좌석은 남습니다).

## 화면 구성

- 현황판: 위쪽 카드 3개(예매 가능 좌석, 예매된 좌석, 매진 구역)와 배치도. 휴대폰에서는 현황판을 누르면 실제 크기로 커져 좌우로 밀어 볼 수 있습니다.
- 카드 숫자: 예매 가능 좌석 = 모든 구역 잔여의 합, 예매된 좌석 = 만석 11,542석 - 예매 가능 좌석. 잔여를 넣지 않은 구역이 있으면 카드에 '정보 없는 구역 N개 빠짐'이 붙고, 그만큼 예매된 좌석이 많게 나옵니다.
- 구역 색: 잔여율 75% 이상, 50~74%, 25~49%, 1~24% 를 보라색 4단계로(원정석은 빨간색 4단계), 매진은 회색, 정보 없음은 흰색 점선, 최대 좌석을 모르는 구역은 잔여만 회색 보라로 표시합니다.
- 구역별 잔여석 표: 구역, 매진 버튼, 잔여, 최대, 잔여율. 잔여가 최대보다 크면 잔여율이 빨갛게 표시됩니다.
- 집계 기록(JSON): '이번 집계 저장'으로 경기 정보, 집계 시각, 모든 구역 숫자를 파일로 저장하고 '저장한 집계 열기'로 다시 엽니다. '저장한 집계를 기준으로'로 비교 기준으로 쓸 수도 있습니다.

### 좌석 수 확인 방법

- 티켓링크 좌석도에서 구역을 열어 좌석 칸을 셉니다 (지금 값도 이렇게 센 것). 확인한 숫자는 표의 '최대' 칸에 넣으면 그 브라우저에 남습니다.
- 예매가 막 열려 팔린 좌석이 없을 때 잔여석을 넣고 '잔여를 최대로 복사'를 누르면 한 번에 들어갑니다. 잔여가 들어간 모든 구역의 최대를 덮어쓰니 예매가 시작된 뒤에는 쓰지 않습니다.
- 모든 사람에게 기본값으로 넣으려면 `index.html` 의 `KNOWN_MAX` 에 추가합니다.

### 만석과 원정석

- 만석 1만 1,542석: 2026-04-05 서울전 기사(https://sports.news.nate.com/view/20260405n12375)의 만석 관중 수입니다. 그날 서울 원정 팬은 1,713명이었습니다.
- 원정석은 평소 1235석이고, 넓게 여는 날은 최대 1713석까지 늘어납니다. 그런 날은 표에서 원정석 '최대'를 바꿉니다 (바꾼 값은 그 브라우저에 남으니 다음 경기 때 다시 1235로).
- 중립석은 기사 뒤인 2026년 8월쯤 새로 생겼습니다. 원정석 쪽 좌석을 나눠 파는 것으로 보고 만석 11,542석은 그대로 씁니다. 다르면 `index.html` 의 `FULL` 을 고칩니다.

## 저장되는 곳

- 입력값은 브라우저 `localStorage`(키 `fc-anyang-seat-status`)에 자동 저장됩니다. 브라우저, 기기마다 따로입니다.
- 집계 기록 파일(JSON) 형식: `{ app: "fc-anyang-seats", version: 1, opp, date, at, base, rows: { 구역: { remain, max } } }`.
  불러올 때는 이 프로그램 파일인지, 숫자는 0 이상 정수인지, 팀은 목록에 있는지, 날짜 형식이 맞는지 확인하고 나머지는 버립니다.

## 스크린샷 인식 방식

- 세로 캡처(앱): 화면 아래 60~90% 를 왼쪽 66%(등급 목록)와 오른쪽 34%(구역 카드)로 나눠 따로 읽습니다. 첫 장은 위쪽 11~20% 에서 상대팀, 경기 일시도 읽습니다.
- 구역 카드("R8구역 / 28석")는 줄 위치만 한글 인식으로 찾고, 이름과 숫자는 영문, 숫자 전용으로 다시 읽습니다. 한 화면의 카드 번호가 이어진다는 점으로 잘못 읽은 번호를 바로잡습니다.
- 같은 구역이 여러 장에 나오면 가장 많이 읽힌 값을 씁니다. 등급 줄의 '석'을 4로 읽는 오류("204석" -> "2044")도 처리합니다.
- 가로 캡처(PC)는 통째로 읽습니다. 코어 4개, 메모리 4GB 이상이면 두 갈래로 동시에 읽습니다.
- 화면 비율을 고정해 두었으므로 다른 기기 캡처를 못 읽으면 `readShot` 의 비율을 조정합니다.

## 개발 메모

- 빌드 과정은 없습니다. `index.html` 을 브라우저로 열면 됩니다.
- 페이지가 열릴 때 `parseText` 자체 시험(`console.assert`)이 돌고, 실패하면 개발자 도구 콘솔에 표시됩니다.
- 추정으로 넣어 둔 곳은 `shortcut:` 주석으로 표시했습니다 (스크린샷 비율).
