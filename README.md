# FC안양 예매현황

FC안양 홈 경기(안양종합운동장)의 티켓링크 구역별 잔여석을 경기장 배치도 위에 그리는 현황판입니다. 서버 없이 `index.html` 한 장으로 동작합니다.

- 주소: https://goormigrm.github.io/fc-anyang-seats/ (GitHub Pages, `main` 브랜치 루트. 푸시하면 바로 반영)
- 검색엔진 노출은 막아 두었습니다 (`noindex`).

실제 작업 순서는 [작업 가이드](https://goormigrm.github.io/fc-anyang-seats/guide/) ([PDF](https://goormigrm.github.io/fc-anyang-seats/guide/guide.pdf))를 봅니다. 입력 화면 맨 위 '작업 가이드', '가이드 PDF' 버튼으로도 엽니다.

## 보기 화면과 입력 화면

| 화면 | 누가 | 보이는 것 |
|------|------|-----------|
| 보기 화면 (기본) | 누구나 | 마지막으로 **발행한** 현황판, 공유 버튼(현황판 저장, 스토리 이미지 저장, 스토리로 공유, 링크 공유, 요약 글 복사). 5분마다 새 발행을 받아 옵니다. 기본 주소는 **홈, 원정 중 가장 최근에 발행한 구장**을 보여 줍니다. |
| 입력 화면 (개발자 모드, PC) | 집계하는 사람 | 위 + 경기 정보, 스크린샷 인식, 구역별 잔여석 표, 발행, 집계 기록, 비교 (이 순서로 칸마다 가로 전체) |

- 입력 화면 켜고 끄기: **Ctrl+Shift+E**. 휴대폰은 주소 끝에 `#edit` 를 붙여 한 번 열면 그 기기는 입력 화면으로 기억합니다. 입력 화면 맨 위 '보기 화면으로' 버튼으로 끕니다.
- 기본 주소 https://goormigrm.github.io/fc-anyang-seats/ 는 홈(`latest.json`)과 원정 구장(`<구장>/latest.json`)의 발행 시각을 비교해 가장 최근 것을 엽니다(같거나 못 읽으면 홈). 늘 안양 홈을 보려면 `?s=anyang`, 김천은 `?s=gimcheon`. 최근 구장으로 옮겨 간 화면은 주소에 `auto` 가 붙고, 열어 둔 사이 다른 구장이 더 최근에 발행되면 5분 안에 그쪽으로 넘어갑니다. 다른 사이트용 화면(`?embed`)도 같습니다. API(`data/latest.json`)는 그대로 홈입니다. 고른 원정 화면(`?s=gimcheon`)의 '링크 공유'는 그 구장 주소, 나머지는 기본 주소를 공유합니다.
- 입력 화면은 숨긴 것일 뿐 비밀은 아닙니다. 다른 사람이 켜도 자기 브라우저에서만 바뀌고, 발행은 GitHub 토큰이 있어야 됩니다.
- 링크를 카톡 등에 보내면 미리보기에 마지막 발행 현황판 이미지가 나옵니다 (메신저가 미리보기를 캐시하면 늦게 바뀜).

## 숫자 넣기 (수작업이 적은 순)

| 방법 | 어디서 | 하는 일 |
|------|--------|---------|
| 1. 보내기 스크립트 | PC 브라우저 + Tampermonkey | 티켓링크 좌석 선택 화면에서 **등급만 차례로 누르면** 열어 둔 현황판(입력 화면) 탭에 숫자가 바로 들어갑니다. 인식 없이 화면 숫자 그대로. |
| 2. PC 화면 복사 | PC 브라우저 | 티켓링크 좌석 선택 화면에서 Ctrl+A, Ctrl+C -> 현황판에서 Ctrl+V. 등급마다 반복. 설치 없음. |
| 3. 캡처 여러 장 | 휴대폰, PC | 티켓링크 앱 '등급/좌석 선택' 캡처, PC 등급 목록 캡처(잘라 낸 것도), 구역 좌석 그림 캡처를 여러 장 한 번에 고르기, 끌어다 놓기, 붙여넣기. 글자 인식(OCR). |
| 4. `현황판 만들기.bat` | 이 PC | 캡처를 bat 파일 위로 끌어다 놓거나 `좌석스크린샷\` 에 넣고 더블클릭. 결과 파일을 만들고 바로 발행. |
| 5. 표에 직접 | 어디서나 | 잔여 칸에 숫자, 매진은 '매진' 버튼. |

보내기 스크립트는 현황판과 **같은 브라우저**에서 티켓링크를 열어야 넘어옵니다(크롬끼리, 웨일끼리). Tampermonkey 저장소가 브라우저마다 따로라서, 현황판은 크롬에 티켓링크는 웨일에 열면 티켓링크 쪽은 보냈다고 해도 현황판에는 안 들어옵니다.

티켓링크 화면 오른쪽 아래 '현황판 보내기: …' 표시로 현황판이 받았는지까지 봅니다.

| 표시 색 | 뜻 |
|------|----|
| 회색 | 대기. 등급/좌석 선택 화면이 아님 (화면에 없는 글자 표시) |
| 빨강 | 예매 화면은 감지했지만 **이 브라우저에 현황판 입력 화면이 없어 못 넘김**. 같은 브라우저에서 현황판(#edit)을 열면 5~10초 안에 한 번 다시 보냄 |
| 보라 | 보냄, 현황판 응답 기다리는 중 |
| 초록 | **현황판이 받음** (받은 시각, 구역 수) |
| 주황 | 현황판이 안 받음 (이유: 다른 구장, 구역 숫자 없음) |

입력 화면 오른쪽 위 **수집 램프**로 지금 자동으로 받고 있는지 봅니다 (보내기 스크립트가 5초마다 보내는 신호로 정함).

| 램프 | 뜻 |
|------|----|
| 꺼짐(회색) | 스크립트 신호 없음. 이 브라우저에 Tampermonkey 와 스크립트(12판)가 켜져 있는지 확인 |
| 노랑 | 스크립트 켜짐, 이 브라우저(이름 표시)에서 연 티켓링크가 없음. 티켓링크를 다른 브라우저에서 열었으면 현황판도 그 브라우저에서 열기 (20초 넘게 신호가 끊기면 마지막 신호 시각 표시) |
| 파랑 | 티켓링크 열림, 등급/좌석 선택 화면이 아님 (화면에 없는 글자: 안양, 등급 선택, N석 중 무엇인지 표시) |
| 초록 | **예매 화면 감지됨.** 등급을 누르면 숫자가 들어옴 |
| 초록 깜빡임 | 1분 안에 숫자 받음 (받은 시각, 구역 수 표시) |
| 빨강 | 다른 구장 예매 화면 (김천 화면에 울산 경기 등) |

받은 글자를 넘긴 이유(다른 구장, 구역 숫자 없음)도 램프 끝에 붙습니다. 예매 화면이 감지되면 램프 둘째 줄에 **좌석 그림 구조**(큰 캔버스, SVG 도형 수, 가장 많은 작은 네모 요소와 속성, 색)가 나옵니다. 구역 총석을 보내기 스크립트로 자동으로 셀 수 있는지 보려는 것입니다(칸이 요소로 그려져 있으면 셀 수 있고, 캔버스면 못 셈). 티켓링크 탭이 여럿이거나 틀(iframe)이 있어도 가장 앞선 상태(예매 화면)를 보여 줍니다.

보내기 스크립트 업데이트: 입력 화면 맨 위 **'보내기 스크립트 설치/업데이트'** 버튼을 누르면 Tampermonkey 업데이트 화면이 뜹니다(거기서 한 번 더 확인). 설치된 판이 최신보다 낮으면 버튼이 보라색으로 'N판 → 최신판'을 보여 주고 램프에도 알립니다(최신 판 번호 `SCRIPT_VERSION` 은 스크립트 `@version` 과 같아야 하고 자동 시험이 맞춰 봄).

보내기 스크립트 설치: 브라우저에 Tampermonkey 확장을 깔고 https://goormigrm.github.io/fc-anyang-seats/fc-anyang-send.user.js 를 열어 설치합니다. 스크립트는 티켓링크 화면 글자를 **읽기만** 하고 클릭, 새로고침, 요청은 하지 않습니다 (아래 '자동화 검토').

### 자동으로 되는 것
- **집계 시각:** 캡처는 가장 늦게 찍은 캡처 시각, 글자 입력은 받은 시각.
- **비교 기준:** 같은 경기에 새 숫자가 들어오면 직전 숫자를 비교 기준으로 잡아, 그 사이 팔린 좌석을 구역마다 +N 으로 보여 줍니다. 보내기 스크립트처럼 10분 안에 이어 들어오는 숫자는 같은 집계로 봅니다.
- **새 경기:** 캡처나 글자의 경기(상대팀, 날짜)가 바뀌면 지난 숫자와 비교 기준을 지우고, 원정석 최대를 평소 값(1235)으로 되돌립니다. 이때는 ⚠ 로 알려 그 집계는 자동 발행하지 않고, 지운 숫자는 하나 보관해 '지난 경기 숫자 되살리기'로 되돌릴 수 있습니다.
- **빠진 구역 하나:** 등급 합계와 나머지 구역으로 계산해 채웁니다 (예: 서포터즈석 79 - R10, R11, R12, R14 = R13).
- **최대 좌석 배우기:** 최대 좌석을 모르는 구역은 처음 들어온 잔여를 최대로 넣고, 잔여가 최대보다 조금(10% 안) 많으면 최대를 늘립니다 (잔여는 실제 좌석 수를 넘을 수 없어서). 예매가 열리자마자 한 번 집계하면 정확하고, 늦게 하면 실제보다 작게 들어갑니다. 이렇게 배운 값은 표에 점선 노란 칸('추정')으로 보이고, 더 큰 잔여가 오면 그만큼 늘어나며, 손으로 고치면 확정됩니다. 넣은 값은 그 브라우저에 남고 발행 JSON 에도 들어가니, 첫 경기 뒤 발행 데이터의 최대를 코드 기본값(`KNOWN_MAX`)으로 옮기면 다른 기기에도 쓰입니다.
- **엉뚱한 화면 무시:** 현황판 구역 숫자가 없는 글자나 캡처(다른 경기 일정 등)로는 경기 정보, 비교 기준, 새 경기 판단을 바꾸지 않습니다. 붙여넣은 글자, 보내기 스크립트 글자는 '안양종합운동장' 경기만 받습니다(원정 경기 화면 무시). 보내기 스크립트는 좌석 선택 화면('등급 선택')에서 경기 정보와 등급, 구역, 숫자 줄만 보냅니다.
- **반쪽 숫자 발행 막기:** 정보 없는 구역이 3개보다 많으면(새 경기 첫 집계 도중 등) 자동 발행을 기다립니다. 예매 가능 좌석이 만석보다 많으면 ⚠.
- **경고:** 등급 합계와 구역 합이 다르거나, 잔여가 최대보다 많으면 알려 줍니다.
- **바로 발행 (선택):** '숫자가 들어오면 바로 발행'을 켜 두면 경고가 없을 때 마지막 입력 30초 뒤 발행합니다 (등급을 차례로 누르는 동안 기다림).
- **모르는 등급 알림:** 현황판 등급표(`GRADES`)에 없는 '...석' 줄은 '현황판에 없는 등급: VIP석 20석'처럼 알려 줍니다. 티켓링크가 등급 이름을 바꾸면 바로 알 수 있습니다.

### 발행
'최신 집계 발행'을 누르면 보기 화면과 다른 사이트가 가져가는 최신 현황(JSON, 현황판 PNG, 스토리 PNG)이 바뀝니다. 몇 초 걸리고, 보는 쪽에는 5분 안에 반영됩니다.

- 처음 한 번 GitHub 토큰을 묻습니다. GitHub 설정 -> Developer settings -> Fine-grained tokens 에서 저장소는 `fc-anyang-seats` 하나만, 권한은 Contents 읽기/쓰기로 만듭니다.
- 토큰은 그 브라우저에만 저장됩니다. 다만 `goormigrm.github.io` 의 다른 페이지도 같은 저장소(localStorage)를 쓰므로 꼭 이 저장소 전용 토큰을 씁니다.
- bat 은 이 PC 의 GitHub 로그인(`gh`)으로 발행해서 토큰이 따로 필요 없습니다. 이 토큰은 권한이 넓어서 페이지 안으로 넘기지 않고, GitHub 요청만 Node 쪽에서 토큰을 붙여 보냅니다(`fcFetch`).
- **시험 발행 지우기:** '마지막 발행 지우기'는 방금 발행을 지우고 바로 전 발행(그때의 추이 기록 포함)으로 되돌립니다. 한 번만 됩니다. '발행 모두 지우기'는 이번 경기 발행(최신, 이번 경기 추이)을 지워 보기 화면을 비웁니다. 경기별 보관(`games/`)과 다른 경기 추이는 남습니다.
- **발행이 겹치지 않게:** 발행과 지우기는 한 번에 하나만 돌고, 다른 탭과는 1분 잠금을 둡니다. 쓰기 직전에 그사이 다른 곳에서 발행했는지 확인해 덮어쓰지 않습니다. GitHub 에서 읽기가 실패하면 빈 기록으로 덮어쓰지 않고 발행을 멈춥니다.

### 이미지와 글
- '추이 이미지': 예매된 좌석 추이를 스토리 크기(1080x1920)로. 지금 예매 수, 직전 집계 대비 증감, 추이 그래프. 휴대폰은 공유 창으로.
- '현황판 저장' 1280x1062(2배 해상도), '스토리 이미지 저장' 1080x1920. 휴대폰에서는 '스토리로 공유'로 공유 창에 바로 보냅니다.
- '요약 글 복사': 인스타, 카톡에 붙일 글 (경기, 기준 시각, 예매 수와 비율, 직전 대비, 매진 구역, 공식 관중).

### 공식 관중
입력 화면 '공식 관중' 칸에 경기 뒤 전광판 관중 수를 넣고 발행하면, 현황판 위쪽, 요약 글, 추이 그래프(금색 점, 마지막 예매 대비), 발행 JSON(`match.attendance`), 경기별 기록에 들어갑니다. 새 경기가 되면 비워집니다.

### 경기별 기록
https://goormigrm.github.io/fc-anyang-seats/season.html : 보관한 지난 경기(`games/`)와 지금 경기의 마지막 집계, 공식 관중, 관중 - 예매, 매진 구역 수를 표와 막대그래프로 봅니다. 보기 화면 맨 아래 '경기별 기록' 링크.

### 발행 토큰 설정
'토큰 설정'으로 새 토큰 넣기, 만료일 적기(30일 전부터 알림), 비밀번호로 잠그기(선택), "삭제" 로 지우기를 합니다. 잠그면 `goormigrm.github.io` 의 다른 페이지가 저장값을 읽어도 토큰을 쓸 수 없고, 탭을 처음 열 때 한 번 비밀번호를 묻습니다(자동 발행 전에 한 번 '최신 집계 발행'으로 풀어 둡니다). GitHub 는 만료일을 브라우저에 알려 주지 않아서 직접 적습니다.

## 원정 경기

- **'북패' 표기:** 사이트 화면(현황판, 구장 버튼, 탭 제목, 상대팀 목록, 경기별 기록)에서는 FC서울을 '북패'로 보여 줍니다. 저장, 공유하는 이미지(현황판 저장, 스토리 이미지, 스토리로 공유)와 요약 글 복사, 발행 데이터(JSON)는 원래 이름 'FC서울', '서울'입니다. 경기장 이름 '서울월드컵경기장'은 그대로입니다.
- **새 구장 그리기:** 축구 전용 구장은 경기장 둘레를 모서리를 둥글게(포항, 울산, 인천) 또는 비스듬히 깎아(전북, 서울) 도는 사각형 위에 칸을 놓습니다(`STADIUMS.<구장>.geo`, `layout`). 칸 글자는 칸 크기를 재서 두 줄 또는 긴 쪽 방향 한 줄로 쓰고 칸에 맞게 줄입니다.
- **티켓링크 구역 이름:** 전북, 포항, 서울, 울산, 인천은 티켓링크가 구역을 어떻게 부르는지 아직 확인하지 못해 구단 좌석도 표기로 칸 이름을 지었습니다. 받은 글자의 구역 이름은 빈칸, 하이픈을 빼고 맞춰 보고(`E-A` → EA), 안 맞으면 한글 앞말을 빼고(`청암E1` → E1), 그래도 안 맞으면 한글을 모두 빼고(`E일반2A` → E2A) 맞춥니다. 등급 이름이 곧 한 칸이면(인천 '원정석', 울산 '프리미엄 테이블석', 포항 '데크석') 등급 숫자를 그 칸에 넣습니다. 끝내 안 맞는 이름은 '현황판에 없는 구역 이름: …'으로 알리고 램프에도 '구역 이름이 현황판과 다름'이 나옵니다. 그 글자를 보내 주면 칸 이름을 맞춥니다.
- **총석:** 김천만 넣어 두었습니다. 다른 구장은 첫 경기 때 구역 좌석 그림을 잘라 넣어 모읍니다(총석을 모르면 카드의 예매 수와 예매율은 '-', 칸은 '잔여N').

- **미판매:** 원정 구장은 이번 경기에 팔지 않는 구역이 있어 표에 '미판매' 버튼이 있습니다. 누르면 빗금으로 칠하고 잔여를 비우며, 다시 누르면 끕니다. 정보 없음, 매진, 합계에서 빠지고 '매진 구역' 카드에 '미판매 N개', 요약 글과 발행 JSON(`unsold`, 구역의 `unsold: true`)에 들어갑니다. **사람이 정한 미판매가 우선입니다:** 티켓링크는 미판매 구역도 0석(매진처럼)으로 보여 주므로, 스크립트, 붙여넣기, 캡처로 숫자가 와도 미판매는 그대로 둡니다. 0보다 큰 잔여가 오면 판매를 시작했을 수 있어 알리기만 하고, 끄는 것은 사람이 합니다(미판매 버튼을 다시 누르거나 표에 숫자를 직접 넣으면 꺼짐). 새 경기로 지워도 미판매 표시는 남습니다. 사람이 누른 미판매는 브라우저에 따로 저장(`fc-anyang-unsold-<구장>`)해, 숫자를 받을 때마다 다시 읽어 지킵니다. 그래서 현황판 탭이 여럿이거나 먼저 열어 둔 탭이 0석을 받아 저장해도 미판매가 지워지지 않습니다(11/07 그렇게 지워진 일). 같은 브라우저의 현황판 탭끼리는 한 탭에서 바꾸면 다른 탭도 바로 맞춥니다.

- **숫자 넣기:** 홈과 같습니다 (보내기 스크립트 12판, 수집 램프, PC 화면 복사, 캡처, 표). 현황판이 경기장 이름(김천종합운동장)을 보고 받으므로, 안양 홈 화면과 김천 원정 화면을 같이 열어 둬도 섞이지 않습니다.
- **배치:** 티켓링크 좌석도대로 위 E(E11~15, E21~25, E31~34), 오른쪽 S(원정 쪽, S11~14, S21~25), 아래 W(W11~14, W21~24, W31~34, 기자석, VIP), 왼쪽 N(N11~14, N21~24)과 트랙 안 가변석 N1~N4. 위치는 대략입니다.
- **총석:** 김천 구역별 총석은 11/07 티켓링크 좌석 그림으로 센 값을 코드(`STADIUMS.gimcheon.max`)에 넣어 두었습니다(N11~N24 스탠드는 그날 미판매라 모름). 새 구장은 구역마다 좌석 그림을 한 번씩 캡처해 넣습니다. 최대 좌석 배우기는 하지 않습니다(늦게 본 잔여가 최대로 들어가 틀어져서).
- **색:** 홈과 같이 예매율로 칠합니다. 보라는 원정 응원 쪽(S), 파랑은 김천 쪽.
- **카드:** 예매된 좌석(원정석을 포함한 판매 구역 전체의 총석 합 대비, 미판매 구역과 잔여나 총석을 모르는 구역은 뺌), 예매율, 원정석 예매(보라 칸 총석 대비, 설명 줄에 예매율과 남은 좌석). 매진, 미판매 구역 수는 예매율 카드 설명 줄에. 추이 그래프도 홈처럼 나옵니다(11/07 10시 전 발행은 예매 수가 없어 점이 없음).
- **등급:** 원정 구장은 등급표가 없어 등급 줄을 '등급: 원정석 650석, ...'처럼 그대로 보여 줍니다.
- **따로 저장:** 입력값은 `fc-anyang-seat-status-gimcheon`, 발행 데이터는 data 브랜치 `gimcheon/` 폴더(`gimcheon/latest.json` 등, `awayRemain` 원정석 잔여, `match.home` 홈 팀). 홈 발행과 서로 지우지 않습니다.
- 다른 사이트용 화면: `?s=gimcheon&embed`.

## 화면 구성

- 현황판: 위쪽 보라 띠(앰블럼, 경기, 집계 시각)와 카드 3개(예매된 좌석, 예매율, 매진 구역 / 원정은 원정석 예매), 배치도. **예매 현황 = 얼마나, 몇 % 예매됐는지**라서 잔여는 설명 줄에만 둡니다. 증감은 구역별로 보이지 않고 아래 추이 그래프(전체)에서만 봅니다. 공유 버튼 상자도 같은 보라색입니다.
- 휴대폰(화면 폭 860px 이하)에서는 인스타 스토리 모양을 위(보라 띠, 카드)와 경기장으로 나눠 보여 줍니다. 경기장을 누르면 경기장 칸만 같은 높이 안에서 크게 커져 상하좌우로 밀어 보고, 다시 누르면 돌아옵니다. 위 카드와 아래 버튼은 그대로입니다. 저장하는 PNG 는 기기와 상관없이 가로판, 스토리 그대로입니다.
- 예매 추이는 **홈석, 원정석 두 그래프**(PC 는 왼쪽 홈석, 오른쪽 원정석, 휴대폰과 추이 이미지는 위아래). 원정석 = 홈 경기는 '원정석' 칸, 원정 경기는 안양 응원 쪽(보라) 칸, 홈석 = 전체 - 원정석. 발행 기록에 `awayBooked`, `awayCap` 를 남기고, 11/07 전 기록은 원정석 숫자가 없어 그래프에서 빠집니다. 공식 관중은 나눌 수 없어 홈석 그래프 위에 글자로(전체 예매 대비).
- 예매된 좌석 추이 (페이지 맨 아래, 현황판과 따로): 발행할 때마다 이번 경기의 예매된 좌석을 점으로 쌓고(PC 최근 8번, 휴대폰 최근 4번), 점 사이에 증감과 걸린 시간을 적습니다. 점선은 마지막 두 집계의 증가 속도가 경기 시작까지 이어질 때 예상입니다. 입력 화면에서는 아직 발행 안 한 지금 숫자도 마지막 점으로 보입니다. 저장 PNG(현황판, 스토리)에는 넣지 않습니다.
- 카드 숫자: 예매된 좌석 = 만석 11,542석 - 모든 구역 잔여의 합, 예매율 = 예매된 좌석 / 만석 (설명 줄에 남은 좌석). 잔여를 넣지 않은 구역이 있으면 카드에 '정보 없는 구역 N개 빠짐'이 붙고, 그만큼 예매된 좌석이 많게 나옵니다.
- 구역 색과 글자: 예매율(총석 대비 팔린 좌석) 75% 이상, 50~74%, 25~49%, 0~24% 를 보라색 4단계로(많이 팔릴수록 진하게, 원정석은 빨간색, 원정 구장의 홈 팀 쪽은 파랑), 칸에는 예매율 %. 1석이라도 남으면 100% 로 보이지 않게 내림. 매진은 회색, 정보 없음은 흰색 점선, 총석을 모르는 구역은 회색 보라에 '잔여N'.
- 구역별 잔여석 표: 구역, 매진(원정은 미판매도), 잔여, 최대, 예매율.
- 집계 기록(JSON): '이번 집계 저장'으로 경기 정보, 집계 시각, 모든 구역 숫자를 파일로 저장하고 '저장한 집계 열기'로 다시 엽니다. '저장한 집계를 기준으로'로 비교 기준으로 쓸 수도 있습니다.

## 저장되는 곳

- 입력값은 브라우저 `localStorage`(키 `fc-anyang-seat-status`)에 자동 저장됩니다. 브라우저, 기기마다 따로입니다. 보기 화면은 이 값을 읽거나 바꾸지 않습니다.
- 그 밖의 키: `fc-anyang-edit`(입력 화면 기억), `fc-anyang-autopub`(바로 발행), `fc-anyang-gh-token`(발행 토큰).
- bat 은 `tools/.profile/` 에 브라우저 프로필을 남겨 다음 실행 때 비교 기준과 바꾼 최대 좌석이 이어집니다. 결과 파일은 `결과\`, 다 쓴 캡처는 `결과\<이름>_캡처\` 로 옮깁니다.
- 집계 기록 파일(JSON) 형식: `{ app: "fc-anyang-seats", version: 1, opp, date, at, base, rows: { 구역: { remain, max } } }`.
  불러올 때는 이 프로그램 파일인지, 숫자는 0 이상 정수인지, 팀은 목록에 있는지, 날짜 형식이 맞는지 확인하고 나머지는 버립니다.

## 스크린샷 인식 방식

- 세로 캡처(앱): 화면 아래 60~90% 를 왼쪽 66%(등급 목록)와 오른쪽 34%(구역 카드)로 나눠 따로 읽습니다. 첫 장은 위쪽 11~20% 에서 상대팀, 경기 일시도 읽습니다.
- 구역 카드("R8구역 / 28석")는 줄 위치만 한글 인식으로 찾고, 이름과 숫자는 영문, 숫자 전용으로 다시 읽습니다. 한 화면의 카드 번호가 이어진다는 점으로 잘못 읽은 번호를 바로잡습니다.
- 같은 구역이 여러 장에 나오면 가장 많이 읽힌 값을 씁니다. 등급 줄의 '석'을 4로 읽는 오류("204석" -> "2044")도 처리합니다.
- 가로 캡처(PC 화면, 잘라 낸 목록, 좌석 그림)는 통째로 한 번 읽고, '이름 … 숫자 석' 목록 줄을 따로 읽습니다. 코어 4개, 메모리 4GB 이상이면 두 갈래로 동시에 읽습니다.
  - 목록 줄: 줄마다 이름 덩어리와 숫자 덩어리를 위치로 자르고, 이름 뒤 '구역'(줄 높이의 0.75 이상인 넓은 글자 조각 2개)과 숫자 뒤 '석'을 떼고 영문+숫자, 숫자 전용으로 읽습니다. 한글 인식기는 E 를 6, W 를 \/, 구역을 7, 석을 4 로 읽기 때문입니다.
  - **크기와 읽기 방식을 바꿔 최대 4번 읽어 같은 값이 두 번 나온 줄만 넣습니다.** 끝까지 안 맞는 줄은 넣지 않습니다(틀린 숫자보다 빈칸이 나음). 그 줄은 표에서 직접 넣습니다.
  - PC 화면 전체면 왼쪽 좌석 칸(꽉 찬 네모)과 큰 그림을 먼저 지워 목록 줄과 섞이지 않게 합니다.
  - **놀티켓 좌석 그림:** 좌석이 동그란 점이라, 가로세로가 비슷하고 넓이가 보통 점과 비슷하면 칸으로 셉니다(작은 원은 꽉 찬 정도가 0.65~0.83 으로 흔들려 네모 기준 0.8 로는 많이 빠짐). 놀티켓은 옆 구역 좌석도 같은 회색으로 그려 잘라 낸 그림에 섞이므로, 칸 간격의 3.3배 넘게 떨어진 칸 덩어리는 옆 구역으로 보고 가장 큰 덩어리만 셉니다(뺀 칸 수는 상태 글에). 한 구역 안 통로(칸 2~3개 폭)는 그대로 이어서 셉니다.
  - **놀티켓은 구역별 잔여를 알려 주지 않음:** 목록은 등급 묶음 합계만('2층 E석(E15~19)' 1,191, '원정석' 1,538) 주고 실시간으로 바뀌어 거꾸로 셈하기 어렵습니다. 그래서 놀티켓 구장은 **구역 좌석 그림 캡처**로 남은 좌석(색 있는 점)과 전체 좌석(모든 점)을 셉니다. 등급 묶음 합계는 그 구역들 합과 맞춰 보기만 합니다(조금 다르면 실시간 차이로 알리고, 크게 다르면 ⚠).
  - **실제 캡처 시험(놀티켓):** 수원삼성 S3 남은 36 / 전체 637, W9 0 / 504(옆 구역 29개 뺌), E15 19 / 843 (`좌석스크린샷/시험_놀티켓/`, 남은 좌석은 사진에서 직접 센 수, 전체는 줄별로 맞춘 수).
  - **한 화면에 안 들어오는 구역:** 나눠 찍은 같은 구역 그림 여러 장을 한 번에 넣으면 더할지 묻습니다([확인] 더함, [취소] 같은 곳을 다시 찍은 것으로 보고 마지막 한 장만). 겹치는 줄 없이 나눠야 맞고, 자른 선에 반쯤 걸린 점은 빠질 수 있습니다. 가능하면 크롬 개발자 도구로 화면을 키워 한 장에 찍습니다(가이드 참고).
  - **좌석 그림 숫자 확인:** 센 남은 칸이 이미 아는 잔여(같이 넣은 목록 글자, 없으면 표의 티켓링크 잔여)와 2석, 3% 넘게 다르면 옆 구역 칸이 섞인 것으로 보고 남은 수도 총석도 넣지 않고 ⚠ 로 알립니다. 센 전체 좌석은 총석이 비어 있을 때만 최대 좌석으로 넣고, 이미 있으면 바꾸지 않고 다르다고 알립니다(아주 옅은 팔린 칸을 못 세거나 옆 구역 칸이 섞이면 틀려서). 잔여는 티켓링크 값을 그대로 둡니다. 잔여를 아직 모르는 구역이면 센 남은 칸을 잔여로 넣습니다.
  - 좌석 그림만 잘라 낸 캡처(등급 목록이 안 보임)는 칸을 색으로 셉니다. 구역 이름은 먼저 그림 전체에서 읽고, 남은 칸(진한 색)이 많아 못 읽으면 칸 바로 위 이름 자리만 잘라 5번 읽어 같은 이름이 두 번 나오거나 한 번 나오고 표의 잔여와 칸 수가 맞을 때 씁니다. 그래도 모르면 센 숫자를 보여 주며 어느 구역인지 묻습니다(취소하면 넣지 않음): 색 있는 칸 = 남음, 밝은 회색 칸 = 팔림. 구역 이름은 그림 안의 가장 큰 영문 글자. 남은 수와 함께 그 구역 전체 좌석 수도 얻어 최대 좌석으로 넣습니다. 꽉 찬 네모(80% 이상)만 칸으로 보고, 줄 번호 숫자와 그림 끝에 잘린 옆 칸은 뺍니다. **구역 총석은 경기마다 같으므로 구역마다 한 번씩만 캡처하면 됩니다** (예: 김천 W11 = 242, 줄별 40, 44, 49, 53, 56).
- 상대팀, 경기 일시는 앞 3장의 맨 위에서 읽어 처음 제대로 읽힌 것을 씁니다 (한 장은 깨지기도 함).
- 인식 도구(`tesseract.js@5.1.1`, jsdelivr CDN)는 처음 인식할 때만 불러옵니다. 보기 화면은 불러오지 않습니다.

## 자동화 검토 (티켓링크, 2026-11-05)

놀티켓(NOL 티켓)은 회차, 잔여석 통신이 로그인 없이 열려 있어 그 통신을 바로 부르는 방식이 됩니다. 티켓링크는 다릅니다.

- 로그인 없이 받을 수 있는 통신(팀 정보, 배너 등)에는 잔여석이 없고, 경기 일정조차 요청, 응답이 암호화돼 있습니다. 자동화 브라우저는 봇으로 감지돼 페이지가 계속 다시 로딩됩니다.
- 잔여석은 로그인한 뒤 예매 창(`/reserve/...`)에서만 나옵니다. 이 경로는 robots.txt 에서 봇 접근을 막아 두었고, 접속 대기열(NetFunnel), 캡차(클린예매), 기기인증, 매크로 의심 차단이 있습니다.
- 이용약관 제32조(매크로 등 프로그램 이용, 허용된 접근범위 초과 시 회원자격 제한, 정지, 상실), 제13조(업무 방해 금지)에 걸릴 수 있고, 계정이 막히면 실제 예매도 못 합니다.
- 그래서 **백그라운드 자동 조회, 자동 캡처, 자동 새로고침은 하지 않습니다.** 사람이 직접 연 화면의 글자를 읽어 오는 방식(PC 화면 복사, 보내기 스크립트, 캡처)까지만 씁니다. 보내기 스크립트도 클릭, 새로고침, 요청을 하지 않습니다.
- 약관 제39조 제2항은 이용으로 얻은 정보를 승낙 없이 영리 목적으로 쓰거나 제3자에게 이용하게 하는 것을 막습니다. 비영리 팬 현황판이지만 다른 사이트에 제공(API)할 때는 이 점을 알고 씁니다. 정식 자동화가 필요하면 티켓링크(NHN링크)나 구단에 데이터 제공을 요청하는 것이 맞습니다.
