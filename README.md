# FC안양 예매현황

FC안양 홈 경기(안양종합운동장)의 티켓링크 구역별 잔여석을 경기장 배치도 위에 그리는 현황판입니다. 서버 없이 `index.html` 한 장으로 동작합니다.

- 주소: https://goormigrm.github.io/fc-anyang-seats/ (GitHub Pages, `main` 브랜치 루트. 푸시하면 바로 반영)
- 검색엔진 노출은 막아 두었습니다 (`noindex`).

실제 작업 순서는 [작업 가이드](https://goormigrm.github.io/fc-anyang-seats/guide/) ([PDF](https://goormigrm.github.io/fc-anyang-seats/guide/guide.pdf))를 봅니다. 입력 화면 맨 위 '작업 가이드', '가이드 PDF' 버튼으로도 엽니다.

## 보기 화면과 입력 화면

| 화면 | 누가 | 보이는 것 |
|------|------|-----------|
| 보기 화면 (기본) | 누구나 | 마지막으로 **발행한** 현황판, 공유 버튼(현황판 저장, 스토리 이미지 저장, 스토리로 공유, 링크 공유, 요약 글 복사). 5분마다 새 발행을 받아 옵니다. |
| 입력 화면 (개발자 모드) | 집계하는 사람 | 위 + 경기 정보, 발행, 집계 기록, 비교, 구역별 잔여석 표, 스크린샷 인식 |

- 입력 화면 켜고 끄기: **Ctrl+Shift+E**. 휴대폰은 주소 끝에 `#edit` 를 붙여 한 번 열면 그 기기는 입력 화면으로 기억합니다. 입력 화면 맨 위 '보기 화면으로' 버튼으로 끕니다.
- 입력 화면은 숨긴 것일 뿐 비밀은 아닙니다. 다른 사람이 켜도 자기 브라우저에서만 바뀌고, 발행은 GitHub 토큰이 있어야 됩니다.
- 링크를 카톡 등에 보내면 미리보기에 마지막 발행 현황판 이미지가 나옵니다 (메신저가 미리보기를 캐시하면 늦게 바뀜).

## 숫자 넣기 (수작업이 적은 순)

| 방법 | 어디서 | 하는 일 |
|------|--------|---------|
| 1. 보내기 스크립트 | PC 브라우저 + Tampermonkey | 티켓링크 좌석 선택 화면에서 **등급만 차례로 누르면** 열어 둔 현황판(입력 화면) 탭에 숫자가 바로 들어갑니다. 인식 없이 화면 숫자 그대로. |
| 2. PC 화면 복사 | PC 브라우저 | 티켓링크 좌석 선택 화면에서 Ctrl+A, Ctrl+C -> 현황판에서 Ctrl+V. 등급마다 반복. 설치 없음. |
| 3. 캡처 여러 장 | 휴대폰, PC | 티켓링크 앱 '등급/좌석 선택' 캡처 여러 장을 한 번에 고르기, 끌어다 놓기, 붙여넣기. 글자 인식(OCR). |
| 4. `현황판 만들기.bat` | 이 PC | 캡처를 bat 파일 위로 끌어다 놓거나 `좌석스크린샷\` 에 넣고 더블클릭. 결과 파일을 만들고 바로 발행. |
| 5. 표에 직접 | 어디서나 | 잔여 칸에 숫자, 매진은 '매진' 버튼. |

보내기 스크립트 설치: 브라우저에 Tampermonkey 확장을 깔고 https://goormigrm.github.io/fc-anyang-seats/fc-anyang-send.user.js 를 열어 설치합니다. 스크립트는 티켓링크 화면 글자를 **읽기만** 하고 클릭, 새로고침, 요청은 하지 않습니다 (아래 '자동화 검토').

### 자동으로 되는 것
- **집계 시각:** 캡처는 가장 늦게 찍은 캡처 시각, 글자 입력은 받은 시각.
- **비교 기준:** 같은 경기에 새 숫자가 들어오면 직전 숫자를 비교 기준으로 잡아, 그 사이 팔린 좌석을 구역마다 +N 으로 보여 줍니다. 보내기 스크립트처럼 10분 안에 이어 들어오는 숫자는 같은 집계로 봅니다.
- **새 경기:** 캡처나 글자의 경기(상대팀, 날짜)가 바뀌면 지난 숫자와 비교 기준을 지우고, 원정석 최대를 평소 값(1235)으로 되돌립니다.
- **빠진 구역 하나:** 등급 합계와 나머지 구역으로 계산해 채웁니다 (예: 서포터즈석 79 - R10, R11, R12, R14 = R13).
- **최대 좌석 배우기:** 최대 좌석을 모르는 구역은 처음 들어온 잔여를 최대로 넣고, 잔여가 최대보다 조금(10% 안) 많으면 최대를 늘립니다 (잔여는 실제 좌석 수를 넘을 수 없어서). 예매가 열리자마자 한 번 집계하면 정확하고, 늦게 하면 실제보다 작게 들어갑니다. 넣은 값은 그 브라우저에 남고 발행 JSON 에도 들어가니, 첫 경기 뒤 발행 데이터의 최대를 코드 기본값(`KNOWN_MAX`)으로 옮기면 다른 기기에도 쓰입니다.
- **엉뚱한 화면 무시:** 좌석 숫자가 없는 글자나 캡처(다른 경기 일정 등)로는 경기 정보, 비교 기준, 새 경기 판단을 바꾸지 않습니다. 보내기 스크립트도 '등급 선택'이 보이는 좌석 선택 화면에서만 보냅니다.
- **경고:** 등급 합계와 구역 합이 다르거나, 잔여가 최대보다 많으면 알려 줍니다.
- **바로 발행 (선택):** '숫자가 들어오면 바로 발행'을 켜 두면 경고가 없을 때 마지막 입력 10초 뒤 발행합니다.

### 발행
'최신 집계 발행'을 누르면 보기 화면과 다른 사이트가 가져가는 최신 현황(JSON, 현황판 PNG, 스토리 PNG)이 바뀝니다. 몇 초 걸리고, 보는 쪽에는 5분 안에 반영됩니다.

- 처음 한 번 GitHub 토큰을 묻습니다. GitHub 설정 -> Developer settings -> Fine-grained tokens 에서 저장소는 `fc-anyang-seats` 하나만, 권한은 Contents 읽기/쓰기로 만듭니다.
- 토큰은 그 브라우저에만 저장됩니다. 다만 `goormigrm.github.io` 의 다른 페이지도 같은 저장소(localStorage)를 쓰므로 꼭 이 저장소 전용 토큰을 씁니다.
- bat 은 이 PC 의 GitHub 로그인(`gh`)으로 발행해서 토큰이 따로 필요 없습니다.
- **시험 발행 지우기:** '마지막 발행 지우기'는 방금 발행을 지우고 바로 전 발행으로 되돌립니다(추이 기록의 마지막 점도 지움). 한 번만 되돌릴 수 있고, 더 지우려면 '발행 모두 지우기'로 보기 화면과 추이 기록을 다 비웁니다.

### 이미지와 글
- '현황판 저장' 1280x1350(2배 해상도, 맨 아래 추이 그래프 포함), '스토리 이미지 저장' 1080x1920. 휴대폰에서는 '스토리로 공유'로 공유 창에 바로 보냅니다.
- '요약 글 복사': 인스타, 카톡에 붙일 글 (경기, 기준 시각, 예매 수와 비율, 직전 대비, 매진 구역).

## 화면 구성

- 현황판: 위쪽 보라 띠(앰블럼, 경기, 집계 시각)와 카드 3개(예매 가능 좌석, 예매된 좌석, 매진 구역), 배치도. 공유 버튼 상자도 같은 보라색입니다.
- 휴대폰(화면 폭 860px 이하)에서는 인스타 스토리처럼 세로판으로 보여 주고, 아래에 큰 글자로 최근 4번 추이를 붙입니다. 현황판을 누르면 크게 보고 좌우로 밉니다. 저장하는 PNG 는 기기와 상관없이 가로판, 스토리 그대로입니다.
- 예매된 좌석 추이 (맨 아래): 발행할 때마다 이번 경기의 예매된 좌석을 점으로 쌓고(최근 8번), 점 사이에 증감과 걸린 시간을 적습니다. 점선은 마지막 두 집계의 증가 속도가 경기 시작까지 이어질 때 예상입니다. 입력 화면에서는 아직 발행 안 한 지금 숫자도 마지막 점으로 보입니다. 스토리 이미지에는 넣지 않았습니다.
- 카드 숫자: 예매 가능 좌석 = 모든 구역 잔여의 합, 예매된 좌석 = 만석 11,542석 - 예매 가능 좌석. 잔여를 넣지 않은 구역이 있으면 카드에 '정보 없는 구역 N개 빠짐'이 붙고, 그만큼 예매된 좌석이 많게 나옵니다.
- 구역 색: 잔여율 75% 이상, 50~74%, 25~49%, 1~24% 를 보라색 4단계로(원정석은 빨간색 4단계), 매진은 회색, 정보 없음은 흰색 점선, 최대 좌석을 모르는 구역은 잔여만 회색 보라로 표시합니다.
- 구역별 잔여석 표: 구역, 매진 버튼, 잔여, 최대, 잔여율. 잔여가 최대보다 크면 잔여율이 빨갛게 표시됩니다.
- 집계 기록(JSON): '이번 집계 저장'으로 경기 정보, 집계 시각, 모든 구역 숫자를 파일로 저장하고 '저장한 집계 열기'로 다시 엽니다. '저장한 집계를 기준으로'로 비교 기준으로 쓸 수도 있습니다.

## 다른 사이트에서 가져가기 (API)

발행할 때마다 `data` 브랜치가 최신 집계 하나로 덮어써집니다. 어느 사이트에서나 브라우저로 바로 받을 수 있습니다 (CORS 허용).

| 주소 | 내용 |
|------|------|
| https://raw.githubusercontent.com/goormigrm/fc-anyang-seats/data/latest.json | 최신 집계 |
| https://raw.githubusercontent.com/goormigrm/fc-anyang-seats/data/latest.png | 현황판 이미지 (2560x2700) |
| https://raw.githubusercontent.com/goormigrm/fc-anyang-seats/data/latest-story.png | 스토리 이미지 (1080x1920) |
| https://raw.githubusercontent.com/goormigrm/fc-anyang-seats/data/history.json | 발행 기록 (추이 그래프용, 최근 500번) `[{ at, opponent, kickoff, booked, unknown }]` |

```js
const d = await (await fetch('https://raw.githubusercontent.com/goormigrm/fc-anyang-seats/data/latest.json')).json();
console.log(d.match.opponent, d.booked, d.capacity, d.updatedAt);
```

| 필드 | 뜻 |
|------|----|
| `version` | 형식 버전 (지금 1) |
| `updatedAt` | 집계 시각 (`2026-11-27T12:00:00+09:00`) |
| `match` | `opponent` 상대팀, `kickoff` 경기 일시, `venue`, `competition` |
| `capacity`, `available`, `booked` | 만석, 예매 가능 좌석(모든 구역 잔여 합), 예매된 좌석(만석 - 예매 가능) |
| `sinceBase` | 직전 집계 이후 `{ at, booked }`, 비교 기준이 없으면 `null` |
| `soldOut`, `unknown` | 매진 구역 id, 잔여 정보가 없는 구역 id (`unknown` 이 있으면 `booked` 가 그만큼 많게 나옴) |
| `sections[]` | `id`, `name`, `grade`(티켓링크 등급), `remain` 잔여, `max` 최대 좌석(모르면 `null`), `sold` 직전 이후 팔린 좌석 |
| `summary` | 요약 글 |
| `images`, `history` | 위 이미지 주소, 발행 기록 주소 |

- GitHub 캐시 때문에 새 발행은 최대 5분 늦게 보일 수 있습니다.
- 바로 전 발행 하나만 `prev/` 에 남기고(되돌리기용) 그 전 것은 남기지 않습니다 (저장소가 커지지 않게). 시각별 예매 수는 `history.json` 에 남고, 구역별 숫자가 필요하면 가져가는 쪽에서 `updatedAt` 별로 저장합니다.

## 최대 좌석 현황

최대 좌석은 43개 중 34개 구역에 들어가 있습니다. 티켓링크 스크린샷 좌석도에서 센 값(11/1 부천전 26개 구역, 10/24 전북전 FS1), myseatcheck.com 의 2025년 좌석도에서 센 값(R6, R7, R12, R13, T1, T2), 원정석 평소 값 1235석입니다.
실제 예매가 열리면 전체를 한 번 대조해 고칩니다. 5석 미만 차이는 현황에 큰 영향이 없어서 그 정도는 그대로 둡니다.
최대 좌석이 없는 구역은 잔여율 색 대신 '잔여만' 회색으로 그려집니다 (카드 합계에는 잔여가 들어감).
아래 9개 구역은 지금 확인할 자료가 없어 비워 두었습니다. 실제 예매가 열리면 확인합니다.

### 좌석 수 확인 방법

- 티켓링크 좌석도에서 구역을 열어 좌석 칸을 셉니다 (지금 값도 이렇게 센 것). 확인한 숫자는 표의 '최대' 칸에 넣으면 그 브라우저에 남습니다.
- 예매가 막 열려 팔린 좌석이 없을 때 잔여석을 넣고 '잔여를 최대로 복사'를 누르면 한 번에 들어갑니다. 잔여가 들어간 모든 구역의 최대를 덮어쓰니 예매가 시작된 뒤에는 쓰지 않습니다.
- 모든 사람에게 기본값으로 넣으려면 `index.html` 의 `KNOWN_MAX` 에 추가합니다.

## 저장되는 곳

- 입력값은 브라우저 `localStorage`(키 `fc-anyang-seat-status`)에 자동 저장됩니다. 브라우저, 기기마다 따로입니다. 보기 화면은 이 값을 읽거나 바꾸지 않습니다.
- 그 밖의 키: `fc-anyang-edit`(입력 화면 기억), `fc-anyang-autopub`(바로 발행), `fc-anyang-gh-token`(발행 토큰).
- bat 은 `tools/.profile/` 에 브라우저 프로필을 남겨 다음 실행 때 비교 기준과 바꾼 최대 좌석이 이어집니다. 결과 파일은 `결과\`, 다 쓴 캡처는 `결과\<이름>_캡처\` 로 옮깁니다.
- 집계 기록 파일(JSON) 형식: `{ app: "fc-anyang-seats", version: 1, opp, date, at, base, rows: { 구역: { remain, max } } }`.
  불러올 때는 이 프로그램 파일인지, 숫자는 0 이상 정수인지, 팀은 목록에 있는지, 날짜 형식이 맞는지 확인하고 나머지는 버립니다.

## 스크린샷 인식 방식

- 세로 캡처(앱): 화면 아래 60~90% 를 왼쪽 66%(등급 목록)와 오른쪽 34%(구역 카드)로 나눠 따로 읽습니다. 첫 장은 위쪽 11~20% 에서 상대팀, 경기 일시도 읽습니다.
- 구역 카드("R8구역 / 28석")는 줄 위치만 한글 인식으로 찾고, 이름과 숫자는 영문, 숫자 전용으로 다시 읽습니다. 한 화면의 카드 번호가 이어진다는 점으로 잘못 읽은 번호를 바로잡습니다.
- 같은 구역이 여러 장에 나오면 가장 많이 읽힌 값을 씁니다. 등급 줄의 '석'을 4로 읽는 오류("204석" -> "2044")도 처리합니다.
- 가로 캡처(PC)는 통째로 읽습니다. 코어 4개, 메모리 4GB 이상이면 두 갈래로 동시에 읽습니다.
- 상대팀, 경기 일시는 앞 3장의 맨 위에서 읽어 처음 제대로 읽힌 것을 씁니다 (한 장은 깨지기도 함).
- 인식 도구(`tesseract.js@5.1.1`, jsdelivr CDN)는 처음 인식할 때만 불러옵니다. 보기 화면은 불러오지 않습니다.
- 화면 비율을 고정해 두었으므로 다른 기기 캡처를 못 읽으면 `readShot` 의 비율을 조정합니다.

## 자동화 검토 (티켓링크, 2026-11-05)

놀티켓(NOL 티켓)은 회차, 잔여석 통신이 로그인 없이 열려 있어 그 통신을 바로 부르는 방식이 됩니다. 티켓링크는 다릅니다.

- 로그인 없이 받을 수 있는 통신(팀 정보, 배너 등)에는 잔여석이 없고, 경기 일정조차 요청, 응답이 암호화돼 있습니다. 자동화 브라우저는 봇으로 감지돼 페이지가 계속 다시 로딩됩니다.
- 잔여석은 로그인한 뒤 예매 창(`/reserve/...`)에서만 나옵니다. 이 경로는 robots.txt 에서 봇 접근을 막아 두었고, 접속 대기열(NetFunnel), 캡차(클린예매), 기기인증, 매크로 의심 차단이 있습니다.
- 이용약관 제32조(매크로 등 프로그램 이용, 허용된 접근범위 초과 시 회원자격 제한, 정지, 상실), 제13조(업무 방해 금지)에 걸릴 수 있고, 계정이 막히면 실제 예매도 못 합니다.
- 그래서 **백그라운드 자동 조회, 자동 캡처, 자동 새로고침은 하지 않습니다.** 사람이 직접 연 화면의 글자를 읽어 오는 방식(PC 화면 복사, 보내기 스크립트, 캡처)까지만 씁니다. 보내기 스크립트도 클릭, 새로고침, 요청을 하지 않습니다.
- 약관 제39조 제2항은 이용으로 얻은 정보를 승낙 없이 영리 목적으로 쓰거나 제3자에게 이용하게 하는 것을 막습니다. 비영리 팬 현황판이지만 다른 사이트에 제공(API)할 때는 이 점을 알고 씁니다. 정식 자동화가 필요하면 티켓링크(NHN링크)나 구단에 데이터 제공을 요청하는 것이 맞습니다.

- 빌드 과정은 없습니다. `index.html` 을 브라우저로 열면 됩니다 (입력 화면은 주소 끝 `#edit`).
- bat 은 처음 실행할 때 `tools/` 에 Playwright 1.63.0 을 설치합니다. 브라우저는 이 PC 의 Playwright 캐시를 씁니다. 다른 PC 에서는 `npx --prefix tools playwright install chromium` 이 필요할 수 있습니다.
- bat 은 경고(⚠)가 있으면 발행 전에 묻습니다. `--no-publish` 를 붙이면 발행하지 않습니다.
- 페이지가 열릴 때 `parseText` 자체 시험(`console.assert`, PC 화면 글자와 등급 합계 채우기 포함)이 돌고, 실패하면 개발자 도구 콘솔에 표시됩니다.
- 추정으로 넣어 둔 곳은 `shortcut:` 주석으로 표시했습니다 (스크린샷 비율).
